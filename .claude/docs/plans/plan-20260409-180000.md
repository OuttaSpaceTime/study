# Implementation Plan: Developer Wiki

**Report location:** `.claude/docs/plans/plan-20260409-180000.md`
**Planning mode:** Mode A (Scout-backed) — `.claude/docs/scouts/001-developer-wiki-20260409.md`
**Date:** 2026-04-09

## TL;DR

Build a personal developer wiki with Obsidian-compatible `[[wikilinks]]` using absolute paths, topic folders, TreeSearch (FTS5) + Ollama (nomic-embed-text) for search, with content entering only through 4 interactive skills. Includes lint script, session logs, `.wiki-index.json`, and an `/obsidian-check` skill.

## Source Requirements (verbatim from scout)

- No raw source ingestion — wiki content only from interactive skills
- Files saved only on explicit "write wiki" command
- Obsidian-compatible `[[wikilinks]]` with absolute paths, deterministic linking
- Obsidian graph renders properly
- Study session logs tracking performance
- Lint at write time (standalone script)
- Progressive deepening — revisiting topics checks understanding via wiki + flashcards
- TreeSearch for fast FTS5 search (<100ms), Ollama for semantic embeddings (<200ms query)
- Developer can ask to present wiki in Obsidian at any point during any skill (requires `snap run obsidian`)

## Objective

Create the wiki infrastructure (directories, scripts, Obsidian config, index), modify 3 existing skills to support "write wiki", create 2 new skills (`/study-walkthrough`, `/obsidian-check`), update `CLAUDE.md` with wiki conventions.

## Before / After

### Before
- `/study-card` writes to `cards/<filename>.md` (flat, no links, no index)
- `/study-flashcard` creates SRS cards only (no wiki output)
- `/study` runs sessions (no logs, no wiki awareness)
- No wiki, no search, no Obsidian vault

### After
- `/study-card` writes to `wiki/<folder>/<slug>.md` with frontmatter, `[[absolute/path]]` links, indexed
- `/study-flashcard` creates SRS cards + companion wiki page with `flashcard_ids` in frontmatter
- `/study` runs sessions + appends to `logs/YYYY-MM-DD.md` + suggests `/study-walkthrough` for weak areas
- `/study-walkthrough` (new) checks wiki + flashcards, calibrates depth, walks through gaps, writes wiki
- `/obsidian-check` (new) launches Obsidian, runs CLI lint suite
- Any skill: developer says "show in Obsidian" → launches app + opens page
- `scripts/wiki-write.sh` orchestrates all write-time operations
- `scripts/lint.sh` validates wiki health

### Execution Flow: "write wiki"

```
Developer says "write wiki"
  → Skill reads wiki/.wiki-index.json
  → Checks if topic exists (extend/split decision)
  → Drafts page content from walkthrough
  → Generates aliases, checks for collisions in index
  → Link resolution:
    - Exact match: scan content for index titles/aliases → [[absolute/path]]
    - TreeSearch: `treesearch search --query "<topic>"` → present related pages
    - Developer confirms links
  → Skill proposes folder from tags, developer confirms
  → Skill writes wiki/<folder>/<slug>.md
  → Skill calls: scripts/wiki-write.sh <path-to-new-file>
    → Updates .wiki-index.json (title, aliases, sections, flashcard_ids)
    → treesearch index --paths wiki/
    → Embeds page via Ollama → appends to .embeddings.json
    → scripts/lint.sh
    → Returns pass/fail + any lint issues
  → Skill reports result, appends to logs/YYYY-MM-DD.md
```

### Execution Flow: "show in Obsidian"

```
Developer says "show in Obsidian" or "open in Obsidian"
  → Check if Obsidian is running: obsidian version 2>/dev/null
  → If not running: snap run obsidian &>/dev/null & disown; sleep 5
  → Open page: obsidian vault=study-wiki open path="<folder>/<slug>.md"
```

### Execution Flow: Progressive deepening (`/study-walkthrough`)

```
Developer runs /study-walkthrough "event sourcing"
  → TreeSearch: find existing wiki pages on topic
  → Ollama cosine: find semantically related pages
  → MCP find_similar_cards: find flashcards on topic
  → Present what exists, ask 1-2 recall questions
  → Calibrate: skip known material, drill gaps
  → Walk through new/weak areas interactively
  → On "write wiki" → extend existing page or create new
  → On "add flashcard" → chain to /study-flashcard
```

**Step 5: Create `scripts/lint.sh`**
- Parse all `[[wikilinks]]` from markdown files in `wiki/`
- Check each resolves to an existing file (absolute path from wiki root)
- Check all links use absolute paths (contain `/` or are single-segment matching a root file)
- Check frontmatter: require `title`, `created`, `tags`
- Check for orphan pages (no inbound links)
- Check for alias collisions across pages (read `.wiki-index.json`)
- Check filename matches slugified title
- Exit 0 if clean, exit 1 with errors listed
- Validates with: run against empty wiki (exit 0), add broken link (exit 1)

**Step 6: Create `scripts/wiki-write.sh`**
- Takes one argument: path to the newly written/modified wiki file
- Reads file frontmatter, updates `.wiki-index.json` entry (title, aliases, sections from H2 headings, tags, flashcard_ids, created, updated)
- Runs `treesearch index --paths wiki/`
- Embeds file content via Ollama API (`curl localhost:11434/api/embeddings`), updates `.embeddings.json`
- Runs `scripts/lint.sh`
- Outputs JSON result: `{"status": "ok", "lint": "clean"}` or `{"status": "ok", "lint": "errors", "errors": [...]}`
- Validates with: write a test page, run script, verify index + search + embeddings

**Step 7: Create `scripts/wiki-search.py`**
- Takes query string as argument
- Embeds query via Ollama API
- Loads `.embeddings.json`, computes cosine similarity
- Returns top-N results with scores
- Validates with: `python3 scripts/wiki-search.py "event sourcing"` returns results

## Open Questions / Blockers

1. **Obsidian vault registration** — Need to launch Obsidian once with the wiki/ folder open to register it as a vault. This is Step 2. If Obsidian doesn't auto-detect, may need `obsidian vault:open` or manual registration.
2. **Graph color groups** — Obsidian graph can color nodes by tag, but the config format for this isn't documented. May need to configure manually in the GUI after first launch.
3. **Eval fixture design** — Evals need a pre-populated wiki state (at least 1-2 pages + flashcards) to test extend/split and progressive deepening. This bootstrapping is Step 15.
4. **`wiki-write.sh` vs Python** — The script needs to parse YAML frontmatter and update JSON. Bash can do it but Python would be cleaner. Decision: use Python for `wiki-write.py` if frontmatter parsing in bash proves brittle.
