# Scout: Developer Wiki / Personal Knowledge Base

**Date:** 2026-04-09
**Status:** IN PROGRESS — Checkpoint 5
**Source:** Karpathy LLM Wiki gist + developer request

## Problem Frame

Transform the `study` repo from a pure SRS flashcard workspace into a **personal developer wiki** — an Obsidian-compatible, interlinked knowledge base that compounds over time. Inspired by Karpathy's LLM Wiki pattern but with a critical twist: **no raw source ingestion**. Content only enters the wiki through interactive skill sessions (`/study-card`, `/study-flashcard`, `/study`, `/study-walkthrough`).

### Key Constraints (ticket-defined)
- No raw source ingestion — wiki content only from interactive skills
- Files saved only on explicit developer command ("write wiki")
- Obsidian-compatible `[[wikilinks]]` with absolute paths and deterministic linking
- Obsidian graph must render properly
- Study session logs tracking performance
- Linting via standalone script at write time; `/obsidian-check` skill for enhanced CLI-based lint
- Start simple
- Progressive deepening — revisiting topics checks understanding + flashcards, then goes deeper

### What Success Looks Like
- Developer runs `/study-card` or `/study` → interactively explores a topic → says "write wiki" → wiki pages are created/updated with proper `[[wikilinks]]`
- Opening `wiki/` in Obsidian shows a connected graph of concepts organized by topic folders
- Session logs track what was studied, when, and how well
- Lint ensures link consistency, orphan detection, frontmatter validity, absolute paths

## Architecture

### Two Layers (Karpathy-adapted)
1. **The wiki** (`wiki/`) — Obsidian vault, topic-organized folders, markdown with frontmatter + wikilinks
2. **The logs** (`logs/`) — Append-only daily session records
3. **Schema** — CLAUDE.md conventions + lint script + skill instructions

### Search Stack
- **TreeSearch** (pytreesearch) — FTS5 + markdown hierarchy, <100ms, section-aware results. Used for: link discovery, extend/split checks, all write-time operations.
- **Ollama** (nomic-embed-text) — Local embeddings pre-computed at write time, stored alongside TreeSearch index. Used for: progressive deepening at session start, semantic "what do I already know about X" queries. Target: <200ms query time.
- **QMD** — Available as escape hatch for cross-wiki queries. Not in critical path.

### Shared "Write Wiki" Flow (Hybrid Module)
Deterministic parts in script, LLM-driven parts in skill instructions.

**Script handles:** index read/write, slug generation, lint, TreeSearch re-index, Ollama embedding
**Skills handle:** content drafting, alias generation, link suggestions, extend/split prompts

### Deterministic Linking Rules
- Wikilinks use **absolute paths** from wiki root: `[[javascript/react/hooks]]`
- Page filename = slugified title: `hooks.md`
- Aliases generated by LLM at write time, checked against index for uniqueness
- Links come from two sources:
  1. **Automatic**: title/alias matching against index (deterministic)
  2. **Interactive**: concepts surfaced during walkthrough (developer-confirmed)
- Lint enforces absolute paths in all wikilinks

## Lint Checks (standalone script)

- Broken `[[wikilinks]]` — target path must resolve to existing file
- All wikilinks use absolute paths (not bare filenames)
- Missing frontmatter fields (title, created, tags)
- Orphan pages (no inbound links from other pages)
- Duplicate titles/aliases across pages
- Filename matches slugified title
