## Query 1 (05:28)

- **Question:** In PostgreSQL, does an UPDATE inside a transaction lock each row, only the row being written at the moment, or all rows for the whole transaction duration?
- **Wiki hits:** [[rails/row-locking-and-concurrency]], [[rails/database-transactions]]
- **Card hits:** none (new card cmra9ohxe created this session)
- **Web check:** confirms — row locks acquired incrementally as rows are touched, held until transaction end (COMMIT/ROLLBACK or savepoint rollback), and never block plain SELECTs (MVCC); only writers/lockers on the same row block. https://www.postgresql.org/docs/current/explicit-locking.html
- **Source:** mixed
- **Answer:** UPDATE takes a row lock per row only as it writes each one (incremental), each held until the transaction commits/rolls back (not per-statement); plain SELECTs never block thanks to MVCC.
