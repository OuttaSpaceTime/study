## Query 1 (10:36)

- **Question:** Cleanest ways to narrow a discriminated union when the discriminant is NESTED (`obj.attributes.kind === 'x'`), given that an inline nested check does not narrow the parent object union.
- **Wiki hits:** none
- **Card hits:** none
- **Web check:** confirms — TypeScript narrows a union only via its own DIRECT discriminant property; a nested/dotted discriminant path does not narrow the ancestor object (open suggestion microsoft/TypeScript#18758; child->parent narrowing "not planned" #50651; nested propagation "working as intended" #57218). https://www.typescriptlang.org/docs/handbook/2/narrowing.html and https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-4.html
- **Source:** research
- **Answer:** Hoisting a top-level literal discriminant onto each member (so `obj.kind` is a direct discriminant) is the cleanest SOUND, guard-free fix; a generic `x is Extract<T,{...}>` type guard works but is an unchecked assertion; extracting the nested discriminant to a local const narrows only the local (or at most the innermost object owning the discriminant), never the parent `obj`.
