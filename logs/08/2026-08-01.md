Deleted `scripts/srs-pressure` and its Python implementation.

The dashboard's "Due for review" is now "Last studied": the pages behind the last 100 reviewed cards, ranked by recency then coverage.

**Why:** Two review schedules competing for the same attention meant wiki pages generated pressure without generating recall, and the flashcard backlog is the one that actually measures retention. Pages read on a timer were being marked "reviewed" without anything being tested. Making the wiki an exploration surface instead — reached from the cards just studied, or browsed freely — keeps it useful without it being a queue to clear. Pressure moved into the MCP server because the verdict and its enforcement have to agree; two implementations of the same thresholds would drift.

**Change:** Applied the findings from a seven-agent review pass (correctness, reuse, simplification, efficiency, altitude) over the whole change.

- **Retention had already drifted.** The TypeScript reimplementation of `scripts/calibration.py` disagreed with it in four ways (min-review floor 20 vs 50, no rating-discrimination guard, UTC instead of local day bucketing, no marginal band). Deleted it: `/flashcards` now shells out to `scripts/study-calibration` and renders its verdict, so one rule has one home.
- **Mixed datetime storage was silently dropping 75% of the review log.** master.db holds both epoch-ms integers and ISO text, and SQLite orders every number before every string, so comparing against an ISO cutoff excluded 1,979 of 2,653 reviews. Correct today only because the integer rows all predate the 30-day window. Every read now normalizes first, ordering still uses the index via two indexed reads merged in JS, and a fixture-DB test pins it.
- Import regression fixed in flashcard-mcp: the new intake gate made `importTxtNotes` throw mid-loop past 10 notes, leaving a partial import. It now checks once, atomically, up front.
- The split-detection heuristic became an explicit `inheritedFrom` column — the heuristic broke when a split was reviewed the same day, which let deck maintenance raise the intake axis it was meant to protect.
- Lint's retired-field denylist became a closed schema, which catches `depth`, `probe_sections`, and `last_probed` that the denylist never named.
- Smaller: dashboard degrades instead of 500ing when master.db is missing; deck overview uses aggregates rather than materializing every card; modal keyboard handling no longer double-fires Enter or steal it from buttons; launcher distinguishes a failed fetch from an empty page and retries; unreachable whole-deck API branch, dead `getReviewActivity`, duplicated colour tables and test fixtures all removed.

**Why:** The reviews caught two classes of thing I could not see from inside the change: a latent data bug that current data happens to mask, and duplication that had *already* diverged rather than might. Both are the kind that surface later as "the numbers disagree and nobody knows which is right".

Also split flashcard-mcp's pressure gate from its report: `assertCanCreateCard` ran the full per-deck fan-out (4 + 5N queries — 9 at one deck, 54 at ten) on every card creation and discarded all of it. The gate is now flat at 2 queries; `check_pressure` keeps the full report for `/study`.

**Verification:** `uv run pytest` 254 passed · ruff clean · `scripts/lint` 0 errors · wiki-viewer 154 tests (up from 123) + typecheck + lint clean · flashcard-mcp 259 tests + typecheck + lint clean · live pages 200 · the viewer's retention now equals the script's by construction (149 reviews, 77.9%, over-difficult).

**Surprising:** the retention numbers matched perfectly on the day I wrote them, which read as "the port is correct" — it actually meant "today's data happens to hide two bugs" (mixed datetime storage, and four rule divergences). Agreement on current data says nothing about agreement on the rule.

**Heuristic:** when porting a statistical rule to a second language, the passing check is not "same output today" but "same output on data that exercises the edges" — or better, don't port it, call it.
