- **Surprising:** `find_similar_cards` is silently Jaccard-only inside the MCP server. `findSimilar` (`card-service.ts:370`) gates the embedding stage on `isEmbeddingsReady()`, and nothing in `src/mcp/server.ts` calls `initEmbeddings()` — so the guard short-circuits before `getEmbedding()`, which would have lazily loaded the pipeline itself. Verified: 0 results cold, 1 result at 58% after `initEmbeddings()`. Same gate at `card-service.ts:128` means `create_card`'s own duplicate guard is word-overlap-only too. Intermittent, not dead: any `getEmbedding` call (e.g. `createCard` line 68 storing a new vector) warms the pipeline for the rest of the process, so checks after a card creation do work.
- **Heuristic:** a readiness guard in front of a lazy loader is a deadlock in disguise — if the only thing that sets the flag is the loader, and the guard gates the call that would run it, the feature is unreachable by design. Ask what initializes the flag, not just what reads it.
