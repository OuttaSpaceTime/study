## Query 1 (11:54)

**Question:** What does `default:` do in a Rails `belongs_to` (e.g. `belongs_to :organization_group, class_name: 'Organization::Group', default: -> { Current.organization.default_group }`)?

**Wiki hits:** none — closest were [[rails/activerecord-preloading]] (0.59), [[rails/foreign-keys]], [[rails/delegated-type]]; all mention `belongs_to` but none cover the `:default` option.

**Card hits:** none (`search_cards "belongs_to default Rails association"` returned empty).

**Web check:** refines: the memory answer said "available since Rails 5.0" — it actually shipped in **Rails 5.1.0** (PR rails/rails#28453, merged 2017-03-17; the 5-1-stable activerecord CHANGELOG carries "Add `:default` option to `belongs_to`"; `:default` is absent from the v5.0 API docs option list and present in v5.1). Everything else confirms against local source `~/.rbenv/versions/4.0.1/lib/ruby/gems/4.0.0/gems/activerecord-8.1.3.1/lib/active_record/associations/builder/belongs_to.rb:104-108` (`model.before_validation { |o| o.association(name).default(&options[:default]) }`) and `belongs_to_association.rb:46-48` (`writer(owner.instance_exec(&block)) if reader.nil?`) — byte-identical in 6.1 through 8.1. Empirically verified on AR 8.1.3.1 + sqlite: not applied by `.new`, applied by `valid?`, explicit value wins, re-applies on update after nulling, dangling FK reads nil so the default overwrites it, and with `belongs_to_required_by_default = true` a nil-returning block still fails validation ("Group must exist"). One nuance the memory answer missed: because the guard is `reader.nil?`, the callback **loads the association on every validation** — a `SELECT` on `groups` appeared during a plain title-only `save!` of a persisted record. Sources: https://github.com/rails/rails/pull/28453, https://raw.githubusercontent.com/rails/rails/5-1-stable/activerecord/CHANGELOG.md

**Source:** memory (verified against local gem source + Rails CHANGELOG; no wiki or card coverage)

**Answer:** `default:` installs a `before_validation` callback that `instance_exec`s the block on the record and assigns the result only when the association currently reads as nil — so it fires per save (not on `.new`), can reference the record's own attributes and `Current.*`, keeps a required `belongs_to` valid, re-applies on update, and overwrites a dangling FK.
