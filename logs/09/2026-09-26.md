# 2026-09-26

## Session 1 — Change (08:06)

**Files:** `.claude/skills/study/SKILL.md`
**Change:** Session Rules now defines how the position line's total is computed: `queueLength` from `start_session` + 1 per `submit_review` that returned `intraDay: true`. It also covers `skip_card` (uses a position, total unchanged), `delete_card` (total unchanged, since the server swaps in a new card) and `adjust_session` (total = rated/skipped + `remainingCards`). Phase 2 step 6 now says an `intraDay: true` rating bumps the total immediately (7/12 rated Again → `Card 8/13`). The intra-day repeats section points to that rule.
**Why:** In a live session, card 7/12 was rated Again and re-queued, but the next card still read "Card 8/12". The old line "the session total grows as repeats are queued" was too easy to overlook. `get_next_card` exposes no position or count, so the skill has to track the total by hand.

## Session 2 — Change (08:09)

**Files:** flashcard-mcp: `src/core/session-service.ts`, `src/mcp/server.ts`, `__tests__/core/session-service.test.ts`. study: `.claude/skills/study/SKILL.md`
**Change:** `get_next_card` now returns `position` (1-based), `total` (current session size) and `repeat` (true for an intra-day learning repeat). The values come from a new `getQueuePosition()` built on `state.pointer` and `state.queue.length`. A new `dropped` counter keeps deleted-card slots out of both numbers, so a skip still uses a position, a topped-up delete leaves the total unchanged, and a delete with no replacement lowers it by one. The tool description names the new fields, and 7 new tests cover a plain serve, the +1 after Again, the repeat serve, skip, both delete cases and an unknown session. The study skill now builds its position line from these fields, and the hand-count rule from Session 1 is gone. The step-6 example is kept, reworded as what the server returns (7/12 rated Again → next serve `position: 8, total: 13`).
**Why:** Replaces the hand-count rule from Session 1. The server owns the queue, so it is the only place that can report the total correctly. The running MCP process picks this up only on restart, and session state lives only in memory, so a restart would lose a session in progress.
