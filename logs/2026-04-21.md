## Session 3 — Change (09:20)
- **Files:** `probes/README.md`, `probes/_template.md`, `.claude/skills/study-walkthrough/SKILL.md`, `AGENTS.md`, `.gitignore`
- **Change:** Added a `probes/` folder as the portable analog of Solveit's live kernel.
  - `probes/README.md` defines the structure (`probes/<topic-slug>/YYYY-MM-DD-HHMM-<brief>.md`) and the four-section probe format (Prediction / Command / Output / Takeaway).
  - `probes/_template.md` is a blank scaffold; underscore prefix keeps it out of topic directories.
  - **Three-tier dependency model** covering Python (`uv`), JavaScript (`npx` / `npm` / `pnpm` / `bun`), and Ruby (`ruby -e` / `bundler/inline` / `Gemfile`) as first-class peers: Tier 1 inline in the command, Tier 2 topic-level env (`probes/<topic>/{pyproject.toml,package.json,Gemfile}` with lockfile committed), Tier 3 promote to a scratch project.
  - `study-walkthrough` Phase 2 Probe bullet now instructs the skill to persist load-bearing probes under `probes/<topic-slug>/` using the template, mirror Takeaways to the session log, and read prior probes for a topic before starting.
  - `AGENTS.md` gains a Probes section pointing to the README.
  - `.gitignore` covers per-topic build artifacts (`.venv/`, `node_modules/`, `vendor/bundle/`, `.bundle/`, `target/`, `__pycache__/`) while keeping lockfiles tracked.
- **Why:** Probes were previously ephemeral — the dev pasted output into chat and lost it at session end. Solveit's whole leverage is that the kernel state *persists within the dialog*. Porting that means probes need a home, a format, and a reproducible command spec. The polyglot dependency model reflects the actual languages the developer works in (Python, JavaScript, Ruby) rather than forcing one runtime; committing lockfiles makes year-old probes re-runnable, which is the whole point.
